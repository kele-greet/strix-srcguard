# SRCGuard

**给 Strix 套的一层合规外壳——即插即用，可以交给 AI Agent 管理，让 Strix 在你守得住的范围里挖洞。**

SRCGuard 不替换 Strix，也不修改它。它在外面包裹 Strix 1.7.0 的二进制：范围由内核强制，模型调用经过策略网关，每一条请求、每一次被拦截的越界尝试都有记录。挖洞仍然是 Strix 的事。

> **SRCGuard 不授予授权。** 它只执行**你**声明的范围。请仅用于你拥有明确、可验证授权的系统。
>
> English: [README.md](README.md) · 命令教程：[docs/zh/tutorial.md](docs/zh/tutorial.md)

## 即插即用

- 只需要指向一个二进制：`strix-1.7.0-linux-x86_64`，不用打补丁、不用重新编译；
- 一条命令预览、一条命令运行、一条命令审计；
- 默认支持 **dry-run** 只生成命令——不发流量、不花钱；
- 预算停车后，用 `--resume` 加预算继续同一个 run，不用从头再来。

整个集成就是一个外壳：`check → gateway → run → audit`。不 fork Strix、不内置源码、不改 `strix-main`。

## 我们做了哪些措施

| # | 措施 | 做什么 | 强度 |
|---|---|---|---|
| 1 | **范围笼子** | 每个 run 一张 nftables 表：只有 scope 解析出的 IP 能出去，其它全部丢弃并记录 | 硬（内核） |
| 2 | **元数据防护** | RFC1918、链路本地、云元数据段一律黑洞，即使解析到也不放行 | 硬（内核） |
| 3 | **速率与突发** | 每主机/全局新连接限速，monitor 里再加滑动窗口请求速率 | 硬 + 监控 |
| 4 | **命令护栏** | MCP `sandbox_exec` 在执行前检查方法、POST 路径、命令配额 | 软（命令层） |
| 5 | **LLM 网关** | 每次模型调用注入范围策略、按价格表计量、成本/token 到顶硬停 | 软 + 记账 |
| 6 | **证据链** | Caido observer、egress 日志、写请求日志、拦截日志、OOB 回调、`compliance.md` | 只读 |
| 7 | **干净停车** | Strix 自己的预算在轮次边界停车（agents=stopped），`--resume` 继续同一个 run | 控制 |

SRCGuard **从不**做的事：选目标、选端点、选 payload；改发现；除策略块外改 Agent 消息；拦范围内流量。

## 会不会影响 Strix 的挖洞能力？先看数据

15 个完成的授权 run（Strix 1.7.0，quick 模式，护栏全开）：

| 指标 | 观测值 |
|---|---|
| HTTP 请求 / 响应 | **2,263 / 1,606** |
| 覆盖 surface / 未关闭 gap | **265 / 119** |
| 写请求（POST 等） | **492 条放行并记录** |
| 被笼子丢弃的越界包 | **43 个**（全是第三方/CDN） |
| 护栏下 Strix 产出的发现 | **3 条**，2 条已手工复现 |
| 完成跑里的 guard kill | **0** |
| 每次模型调用额外注入 | ~70–100 token / 60–80K 上下文 → **<0.2%** |

Agent 的请求量和覆盖面保持正常（单 run 71–261 请求、14–30 个 surface）。护栏只碰边缘流量：一次交战中几十个越界包被丢弃，同时几百条范围内的写请求原样放行。而且 **Strix 在护栏下照样挖到了真问题**——CWE-209 堆栈泄露、CWE-639 未授权附件下载，两条都手工复现过。

**结论：护栏是边界级的，不是能力级的。** 范围内流量的网络路径没有变化——内核里多一条 accept 规则；而 Caido 本来就是 Strix 默认栈的一部分，SRCGuard 只是读它。

只有四件事会改变 Strix 的行为，而且都是策略选择、不是拦截：instruction 文本、轮数/预算上限、可选的 `--caido-tamper`（把被禁方法改写成 GET）、可选的 `--docker-proxy`（去掉沙箱特权）。其余全是被动。

> 早期版本确实打断过扫描（dns4 集合为空、限速规则写反）。那是 bug，不是设计上限；都已修复，153 个测试覆盖。

## 交给 AI Agent

这个仓库就是写给 AI Agent 操作的。把仓库给它，然后说：

```text
你现在操作 SRCGuard。先读 AGENTS.md，再读 docs/zh/tutorial.md。
先向我确认：书面授权、精确的 in-scope host、允许的方法与速率、预算。
然后按 check → gateway → dry-run → launch → audit 执行。绝不扩大范围。
报告：测了什么、拦了什么、还剩哪些 gap、网关计量成本。
```

`AGENTS.md` 是操作契约（范围、停止规则、预算、证据、报告），多数 Agent 运行时会自动读取。

## 授权与责任 —— 跑之前先读

SRCGuard 是工具，不是授权。它无法验证你有没有权限测试某个目标。

**把 host 写进 `in_scope`，就等于你为这次交战中签了授权声明/责任书。** 你声明：你持有资产
所有者的明确书面许可；你为这个范围内发出的每一条请求负责；如果这份许可不存在，后果由你承担。
请把书面授权（邮件、工单、合同）和 run 产物放在一起——scope 文件加那份证明，就是责任书。

跑之前请预估这些问题：

- **漏报** —— 没发现不等于目标安全；覆盖不到的面会如实记为 gap。
- **误报** —— Agent 的发现可能是错的，提交给任何人之前先手工复核。
- **目标影响** —— 即使 1 rps，探测也可能触发 WAF/IDS、封你的 IP、影响脆弱业务。
- **数据暴露** —— 范围内读取可能带回真实用户数据/PII，如何最小化和处理是你的责任。
- **Agent 误判** —— 自主 Agent 可能尝试越界或改状态的动作；笼子和护栏会拦截/记录，但没有任何护栏能接住每一次尝试。
- **残留** —— 登记/上传测试可能留下测试数据，测试后请清理或在报告里说明。
- **预算** —— LLM 调用要花钱；上限是安全网，不保证账单固定。
- **第三方** —— Strix、Caido、Cloudflare 隧道、容器镜像、模型提供方都是外部依赖，有各自的条款、可用性和风险。
- **法律** —— 未授权测试在多数司法辖区是刑事犯罪。本项目不提供法律意见。

不提供任何担保（MIT）。作者不对滥用、也不对你授权的运行造成的损失负责。

## 诚实的边界

- nft 笼子是**唯一的硬网络边界**；方法与路径规则是命令层或事后的（Caido 这个版本不能丢弃请求）；
- `--caido-tamper` 把被禁方法改写成 GET（降级，不是 drop）；
- 没有 DNS 权威 OOB，只有 HTTP 回调；
- 被笼子丢掉的越界 host 记为 `blocked_attempt`，不杀扫描。

## 数据脱敏

本仓库不发布任何真实目标的漏洞细节，`evidence/` 只有本地 lab 证明。run 目录、网关日志、cookie、key 都在 `.gitignore`。你要发布自己的结果时，先打码 host、token 和未修复细节，直到厂商修复。
